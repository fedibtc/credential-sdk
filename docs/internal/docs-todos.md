# Documentation TODOs

This document tracks the plan for turning the current generated API reference
into a useful documentation site for application developers, protocol readers,
and AI coding agents.

The library is already mostly stable. The documentation work should therefore
focus on clarity, examples, architecture, and navigation rather than redesigning
the API.

## Goals

- Help a developer issue, hold, verify, and revoke a credential without reading
  tests or Rust implementation details.
- Explain the protocol architecture and trust boundaries clearly enough for
  application integrators to use the SDK correctly.
- Keep generated TypeDoc API reference, Rust implementation docs, and narrative
  guides connected without duplicating too much content.
- Make the docs pleasant to browse on GitHub Pages.
- Publish machine-readable docs that AI coding agents can retrieve and cite.

## Documentation Architecture

Use TypeDoc as the hosted documentation shell for now:

- `README.md` remains the landing page.
- Markdown guides live in `docs/` and are included with TypeDoc
  `projectDocuments`.
- TypeScript/WASM API reference remains generated by TypeDoc from the generated
  package declarations.
- Rust docs are generated separately by `cargo doc` and linked from the TypeDoc
  site.
- AI-oriented Markdown files are generated or maintained alongside the HTML
  output.

This keeps the current stack small. If the docs later need versioning, richer
navigation, or fully unified TypeScript plus Rust search, reconsider a dedicated
docs framework such as VitePress, Docusaurus, or MkDocs.

## Information Architecture

Target a Diataxis-style split:

- **Start Here**: quickstart, install/build notes, first working credential flow.
- **Guides**: task-focused instructions for real integration work.
- **Concepts**: architecture, protocol flow, privacy model, revocation model,
  canonicalization, trust boundaries.
- **Reference**: generated TypeDoc, wire formats, errors, Rust API docs.
- **Security**: operational guidance, sensitive state, verifier obligations,
  known limitations, audit checklist.
- **AI Docs**: curated index and compact implementation summary for agents.

### 8. Rust Docs Integration

Yes, Rust docs can be included in the same hosted documentation site. The
recommended first step is to generate rustdoc separately and host it next to the
TypeDoc output.

Recommended initial approach:

- [x] Add a script such as `docs:rust` that runs
      `cargo doc --workspace --no-deps`.
- [x] Copy or generate the rustdoc output into a subdirectory of the TypeDoc
      Pages artifact, for example `dist/docs/api/rust/`.
- [x] Add a TypeDoc sidebar entry named `Rust API` pointing to the generated
      rustdoc output.
- [x] Ensure the GitHub Pages workflow builds both TypeDoc and rustdoc before
      uploading `dist/docs/api` through `pnpm run docs`.
- [x] Add a short Markdown page, `docs/rust-api.md`, explaining that Rust API
      docs are generated by rustdoc and live under the linked Rust API section.

Tradeoffs:

- Hosting rustdoc beside TypeDoc gives one domain and one deployment artifact,
  but separate navigation and search.
- Fully merging TypeScript and Rust docs into one navigation and search
  experience likely requires a separate docs framework and generated Markdown
  reference pages.
- Rustdoc JSON can be useful for tooling, but it is not the lowest-risk first
  step. Prefer HTML rustdoc plus curated Markdown summaries unless a concrete
  AI/tooling consumer needs JSON.

Future unified-docs option:

- [ ] Evaluate `typedoc-plugin-markdown` for Markdown TypeScript API output.
- [ ] Evaluate whether Rust API docs should remain rustdoc HTML or be summarized
      into Markdown pages.
- [ ] If unified search/navigation becomes important, prototype a VitePress,
      Docusaurus, or MkDocs site that mounts narrative docs, generated TypeScript
      Markdown, and links to rustdoc.

## Definition of Done

- A new user can complete issuance, verification, and revocation by reading the
  quickstart and one guide.
- A protocol reviewer can understand issuer, holder, verifier, blinding,
  canonicalization, and revocation from concept pages.
- TypeDoc has meaningful descriptions and examples for every exported TypeScript
  symbol.
- Rust docs are reachable from the same hosted docs domain.
- The site has working search over narrative docs and API comments.
- GitHub Pages publishes the full docs artifact.
- `llms.txt` and `llms-full.txt` exist and point agents at canonical docs.
